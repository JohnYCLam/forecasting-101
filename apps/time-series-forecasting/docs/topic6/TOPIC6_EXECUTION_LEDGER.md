## Subsection 6.1: From a Time Series to a Supervised-Learning Table

### 1. Claim
A standard regressor can forecast a time series only after each forecast origin and horizon is converted into a leakage-safe tabular row; autoregressive lags and renewables must be frozen at the forecast origin while forward calendar signals advance; training on target load causes artificial error collapse, while deployment yields severe error; and target-day calendar features are required to restore the weekly demand shape in pooled direct regression.

### 2. Plain-Language Definitions
- **Supervised Table:** Converting chronological time series into a 2D matrix of input feature rows matched with future target values.
- **Pooled Direct Multi-Step Regressor:** We fit one separate StandardScaler -> Ridge(alpha=10) pipeline for each safe feature set. Within a feature set, that one Ridge model is pooled across all 168 origins and 30 horizons (5,040 rows) conditioning on horizon step $h$. The model emits one scalar prediction per row; 30 scalar predictions are assembled into the 30-day forecast trajectory. It is not recursive, not one-step, not a 30-output vector, and not 30 separate horizon models.
- **Origin-Window Rolling Feature:** Moving-window statistics calculated strictly on historical observations ending at forecast origin $T$ (`y.shift(1).rolling(w)` ending at $T$), preventing inclusion of future information; these windows end at origin $T$, so they are known and frozen across all horizons and safe relative to $y(T+h)$.
- **Extreme Lookahead Leakage:** Training with `target_load = y(T+h)` (the future target load of the day being predicted), causing artificial error collapse.
- **Invalid Holdout Score:** Evaluating the leaky model with unobserved future actuals passed as `target_load` (not a valid forecast).
- **Production Leak Forecast:** Replacing the missing future target in deployment with load known on the origin cutoff day (`2019-09-30`), exposing the severe error penalty (4,506.22 MW).
- **Seasonal Naive Benchmark:** An unfitted heuristic benchmark forecasting future days by copying the value observed exactly one seasonal cycle earlier (7-day persistence). It is not a fitted Ridge feature representation.

### 3. Dataset & Sample Scope
- **Dataset:** German Daily Electricity Load (`references/boost-vs-forest-ts/data/de_electricity_load_daily.csv`, 2,100 days, 2015-01-01 to 2020-09-30, MW). Price is recorded in the source data but is not used as a predictor by this 6.1 Ridge regressor.
- **Fit:** 168 origins, every second day, 2018-10-01 through 2019-08-31; each origin supplies horizons 1..30 (total 5,040 training rows); Ridge alpha 10; scaler fit on those rows only.
- **Forecast Origin ($T$):** 2019-09-30.
- **Holdout Test Range:** 2019-10-01 to 2019-10-30 ($H = 30$ days).

### 4. Features, Availability & Protocol
- **Target Horizon:** Multi-step planning horizon $h = 1 \dots 30$ days. Each row has one scalar target $y(T+h)$.
- **Feature Groups for Safe Ablation (Strictly 3 Choices):**
  - *Group 1 (History + horizon):* `["lag_1", "lag_2", "lag_3", "lag_7", "lag_14", "lag_28", "h", "h_sin", "h_cos"]` (9 features).
  - *Group 2 (+ origin-window rolling):* Group 1 + `["roll_7", "roll_28"]` (11 features).
  - *Group 3 (Full safe):* Group 2 + Calendar (`"dow_sin", "dow_cos", "is_weekend"`) + strictly lagged renewables (`"solar_lag1", "wind_lag1"`) (16 features).
- **Separate Benchmark:** Seasonal Naive (7-day persistence heuristic, not a feature representation).
- **Separate Leakage Diagnostic:** Target-load model (`["target_load", "h", "h_sin", "h_cos"]`, intentionally invalid diagnostic).
- **Protocol:** Fit one separate StandardScaler -> Ridge(alpha=10) pipeline for each safe feature set; within a feature set, that one Ridge model is pooled across all 168 origins and 30 horizons (5,040 rows); score 30 October holdout rows where features are frozen at origin $T$; compare training vs invalid holdout vs production test MAE across feature groups.

### 5. Models, Tuning Budget, Baselines & Default State
- **Benchmark:** Seasonal Naive (unfitted 7-day persistence).
- **Primary Model:** One separate StandardScaler -> Ridge(alpha=10.0) pipeline for each safe feature set; within each set, one model is pooled across all 168 origins and 30 horizons.
- **Leaky Model:** Intentionally invalid diagnostic Ridge Regression trained on Group 4 with `target_load = y`.
- **Default UI State:**

## Subsection 6.2: One Table, Three Ways to Learn: Ridge, Random Forest, Boosting

### 1. Claim
On identical tabular features, Ridge fits a single additive hyperplane, Random Forest averages independent orthogonal partitions to reduce variance, and Gradient Boosting iteratively targets residual errors to capture sharp nonlinear interactions.

### 2. Plain-Language Definitions
- **Ridge Regression:** A linear model finding one global slope per feature; cannot capture nonlinear bends or feature cross-products without manual polynomial terms.
- **Random Forest:** An ensemble of parallel, deep decision trees trained on bootstrap samples; averages piecewise constant steps to smooth noise and reduce variance.
- **Gradient Boosting (XGBoost):** An ensemble of sequential shallow trees where each new tree fits the residual errors (gradients) of the existing ensemble using second-order Taylor approximations.
- **Nonlinear Interaction:** When the effect of one input (e.g. temperature) on the output changes abruptly based on another input (e.g. weekday vs weekend).
- **Complexity / Overfitting:** Shallow trees underfit by clipping extremes; excessively deep trees overfit by chasing idiosyncratic noise spikes.

### 3. Locked Synthetic Data-Generating Process (DGP)
To test algorithmic mechanisms cleanly without cherry-picking real test slices, the DGP is mathematically locked:
- **Sample Length:** $T = 730$ days (2 full daily years).
- **Random Seed:** Locked at `42`.
- **Exogenous Temperature ($T_t$):**
  $$T_t = 16.0 + 10.0 \sin\left(\frac{2\pi t}{365}\right) + \varepsilon_t^T, \quad \varepsilon_t^T \sim \mathcal{N}(0, 1.5^2)$$
- **Calendar Signals:** Day of week $w_t = t \pmod 7$; Weekend indicator $W_t = \mathbb{I}(w_t \in \{5, 6\})$.
- **Base Demand:** $50.0$ MW $+ 12.0 \cdot (1 - W_t)$ (weekday commercial activity shift).
- **Heating Response ($T_t < 18^\circ\text{C}$):** $+0.6 \cdot \max(0, 18 - T_t)$.
- **Nonlinear Cooling Interaction ($T_t \ge 24^\circ\text{C}$):**
  $$S_t = 3.5 \cdot \left[\max(0, T_t - 24)\right]^2 \cdot (1.0 - 0.70 W_t)$$
  *(Air conditioning causes an explosive quadratic surge on hot weekdays; on weekends, commercial cooling is suppressed by 70%).*
- **Autoregressive Continuity:** $+0.25 (y_{t-1} - 50.0)$.
- **Observation Noise:** $\varepsilon_t \sim \mathcal{N}(0, 1.8^2)$.

### 4. Train, Validation, Test Ranges
- **Train Split:** Days 1 to 520 (17.3 months).
- **Validation Split:** Days 521 to 620 (for complexity parameter checking).
- **Test Split:** Days 621 to 730 (110 days, capturing late-summer heat surge).

### 5. Features, Availability & Protocol
- **Feature Set:** $[T_t, W_t, w_t, y_{t-1}, y_{t-7}]$.
- **Protocol:** Fit on Train ($t \le 520$); evaluate residual distributions and conditional predictions on Test ($t > 620$) across the temperature spectrum.

### 6. Models, Tuning Budget & Default State
- **Ridge:** `Ridge(alpha=1.0)`.
- **Random Forest:** `RandomForestRegressor(n_estimators=100, max_depth=6, min_samples_leaf=3, random_state=42)`.
- **Gradient Boosting (XGBoost):** `xgb.XGBRegressor(n_estimators=100, max_depth=4, learning_rate=0.08, min_child_weight=3, subsample=0.85, colsample_bytree=0.85, random_state=42, tree_method="hist")`.
- **Complexity Slider:**
  - *Underfit:* `max_depth = 2`
  - *Balanced:* `max_depth = 4` (XGBoost) / `6` (RF)
  - *Overfit:* `max_depth = 14`, `min_child_weight = 1`
- **Metric:** Overall Test MAE and Regime Residual Variance for extreme heat days ($T_t > 24^\circ\text{C}$).
- **Default UI State:**
  - Active View: `"Model Comparison (Ridge vs RF vs XGBoost)"`
  - Complexity: `"Balanced"`
  - Highlight: `"Heat Surge Regime (T > 24°C)"`

### 7. Expected Observable in Default Chart
- In the temperature vs load scatter and residual view:
  - **Ridge** exhibits a systematic curved residual pattern in the high-temperature weekday region (under-predicting extreme heat by 10–20 MW because linear slopes cannot bend quadratically).
  - **Random Forest** captures the step increase with a piecewise constant plateau, visibly smoothing the extreme peak.
  - **XGBoost** follows the sharp quadratic rise closely, achieving the lowest residual error in the high-heat corner.
  - Shifting complexity to "Underfit" cuts off the peak across all tree models; "Overfit" produces sharp erratic spikes that chase training noise.

### 8. Falsifier & Mitigation
- **Falsifier:** Ridge achieves comparable or lower MAE than tree ensembles in the extreme heat regime ($T_t > 24^\circ\text{C}$), or residual plots show no systematic curvature for Ridge.
- **Mitigation:** If noise obscures the quadratic curvature, reduce noise scale $\sigma_\varepsilon$ from 1.8 to 1.2 before locking generator output.

## Subsection 6.3: The Forecast Arena: Fair Comparison with Sections 1–5

### 1. Claim
Machine learning does not universally outperform classical models; gradient boosting excels when external covariates and complex calendar interactions dominate, while Random Forest and SARIMA remain superior or competitive on calm seasonal periods.

### 2. Plain-Language Definitions
- **Walk-Forward Validation:** Testing models across several expanding chronological windows to prevent single-period bias.
- **Direct Multi-Horizon:** Mapping features available at forecast origin $T$ (plus horizon step $h$) directly to future target $y_{T+h}$, avoiding recursive error accumulation.
- **Feature Ablation:** Comparing forecast accuracy as feature groups are incrementally added to quantify the value of each signal.
- **Permutation Importance:** Assessing feature importance by measuring error inflation when a feature column is randomly shuffled.
- **Gain Size:** The median or mean percentage reduction in forecast error, which must accompany win rate to prevent claiming victory on trivial margins.

### 3. Dataset & Sample Scope
- **Dataset:** German Daily Electricity Load (`references/boost-vs-forest-ts/data/de_electricity_load_daily.csv`).

## Subsection 6.4: Multi-Step Forecasting: Recursive or Direct?

### 1. Claim
Recursive multi-step forecasts accumulate autoregressive errors as lead time increases, whereas direct multi-horizon models avoid error feedback at the cost of training separate target mappings.

### 2. Plain-Language Definitions
- **Recursive Forecasting:** Training a single 1-step model $\hat{y}_{t+1} = f(y_t, y_{t-1}, \dots)$ and iteratively feeding predicted values back into the feature vector for subsequent steps $\hat{y}_{t+2}, \hat{y}_{t+3}, \dots$
- **Direct Forecasting:** Training models to predict $\hat{y}_{t+h}$ directly from origin features $X_t$, bypassing intermediate predictions.
- **Error Cascading (Compounding):** When an error at step $h=1$ corrupts the inputs for step $h=2$, causing forecast divergence over long horizons.
- **Lead Day ($h$):** The number of days into the future being forecast ($h = 1, \dots, 30$).

### 3. Dataset & Sample Scope
- **Dataset:** German Daily Electricity Load (`de_electricity_load_daily.csv`).
- **Training Period:** 2015-01-01 to 2019-12-31.
- **Evaluation Holdout:** 2020-01-01 to 2020-01-30 ($H = 30$ days, winter demand).

### 4. Target, Horizon & Protocols
- **Target:** Daily load $y_{T+h}$ for $h \in [1, 30]$.
- **Recursive Protocol:** 
  - Model fits 1-step target $y_{t+1}$ using $[y_t, y_{t-1}, y_{t-2}, y_{t-6}, y_{t-7}, \text{dow}_{t+1}, \text{month}_{t+1}]$.
  - For $h = 1 \dots 30$, predicted $\hat{y}_{T+h-1}$ is appended to the historical buffer to construct the feature row for step $h$.
- **Direct Protocol:**
  - Model fits horizon target $y_{t+h}$ directly using $[y_t, y_{t-1}, y_{t-2}, y_{t-6}, y_{t-7}, \text{dow}_{t+h}, \text{month}_{t+h}, h, \sin(2\pi h/30), \cos(2\pi h/30)]$.

### 5. Models, Baselines & Default State
- **Recursive XGBoost:** `xgb.XGBRegressor` (1-step recursive roll).
- **Direct XGBoost:** `xgb.XGBRegressor` (direct multi-horizon).
- **Recursive Random Forest:** `RandomForestRegressor` (1-step recursive roll).
- **Direct Random Forest:** `RandomForestRegressor` (direct multi-horizon).
- **Baseline:** Seasonal Naive (7-day persistence).
- **Metric:** MAE by Lead Day $h \in [1, 30]$ and Cumulative 30-day MAE.
- **Default UI State:**
  - Active View: `"MAE by Lead Day Curve & Forecast Path"`
  - Active Model: `"XGBoost (Direct vs Recursive)"`
  - Selected Lead Step: `h = 15`

### 6. Expected Observable in Default Chart
- At lead $h=1$, direct and recursive XGBoost have virtually identical MAE (~1,200 MW).
- Beyond $h=7$, recursive MAE rises significantly faster than direct MAE, visibly compounding errors during an unexpected mid-month temperature dip.
- The direct model maintains a flatter error trajectory across days 10–30, proving the advantage of insulating long horizons from step-level prediction noise.

### 7. Falsifier & Mitigation
- **Falsifier:** Recursive forecasting shows lower error than direct forecasting at lead $h=30$, or recursive error exhibits zero increase across the 30-day horizon.
- **Mitigation:** Verify that the recursive loop does not read actual future values from the test set (a common leakage bug). Confirm direct models receive the explicit horizon parameter $h$.

## Subsection 6.5: Where Tree Models Fail: Trend, Extrapolation, and Drift

### 1. Claim
Tree ensembles cannot predict values outside the range of their training targets; when a series trends upward or experiences regime shift, raw level trees flatline at historical boundaries, while differenced/detrended trees or statistical trend models extrapolate successfully.

### 2. Plain-Language Definitions
- **Extrapolation Failure:** Decision trees partition feature space into bins and output the leaf mean. If test inputs fall outside all training bins, trees output the edge boundary leaf value; they cannot project an upward slope.
- **Target Detrending:** Removing a linear trend $\hat{\mu}_t = a + bt$ from the training series, training the tree on stationary residuals, and adding the projected trend back to future forecasts.
- **Target Differencing:** Training the tree on first differences ($\Delta y_t = y_t - y_{t-1}$) and integrating predictions back to levels.
- **Concept Drift:** When the underlying relationship between inputs and outputs changes fundamentally, requiring model retraining or rolling estimation.

### 3. Locked Synthetic Trend Break DGP
To cleanly isolate the mathematical leaf boundary constraint, a controlled trend dataset is locked:
- **Sample Length:** $T = 500$ days.
- **Random Seed:** Locked at `101`.
- **Underlying Linear Trend:** Starts at $100.0$ MW with constant growth $+0.25 \times t$.
- **Weekly Seasonality:** $+10.0 \sin(2\pi t / 7)$.
- **Additive Noise:** $\varepsilon_t \sim \mathcal{N}(0, 2.0^2)$.
- **Training Window:** $t = 1 \dots 350$. Target range is strictly bounded: $\min(y_{train}) \approx 98$ MW, $\max(y_{train}) \approx 192$ MW.
- **Test Holdout (Extrapolation Window):** $t = 351 \dots 500$ (150 days). During this test window, the true series continues rising to $y \in [195, 230]$ MW—strictly above the maximum training value.

### 4. Models, Baselines & Default State
- **Model A (Raw Level Tree):** `xgb.XGBRegressor` trained directly on $[t, \text{lag}_1, \dots, \text{dow}]$ to predict $y_t$.
- **Model B (Detrended Tree):** Linear trend fit on training data; XGBoost fits residuals; forecast reconstructs level via $\hat{y}_{t+h} = \hat{a} + \hat{b}(t+h) + \hat{e}_{t+h}$.
- **Model C (Differenced Tree):** XGBoost trained on $\Delta y_t$; forecasts cumulatively summed from origin $y_T$.
- **Baseline D (Statistical Trend):** Holt's Linear Exponential Smoothing.
- **Metric:** Extrapolation Holdout MAE and Maximum Forecasted Level $\max(\hat{y})$.
- **Default UI State:**
  - Active View: `"Extrapolation Plateau vs Detrended Recovery"`
  - Display Range: $t = 250 \dots 500$
  - Reference Line: Training Maximum Boundary ($192.4$ MW)

### 5. Expected Observable in Default Chart
- As the test series crosses $t=350$ and climbs above $192$ MW, the Raw Level XGBoost forecast visibly flatlines into a flat horizontal ceiling at exactly $\max(y_{train}) \approx 192$ MW.
- In stark contrast, the Detrended Tree, Differenced Tree, and Holt's Linear follow the rising slope up to $225+$ MW.
- The diagnostic panel displays the rolling error of the raw level tree diverging rapidly, showing learners why trees should never be deployed on non-stationary levels without detrending or differencing.

### 6. Falsifier & Mitigation
- **Falsifier:** The raw level tree outputs any predicted point higher than the training maximum ($>193.0$ MW), or detrending fails to reduce extrapolation test MAE by at least 40%.
- **Mitigation:** Ensure tree implementation does not have linear leaf extrapolation enabled. Verify detrending coefficients $\hat{a}, \hat{b}$ are computed strictly on training indices $1 \dots 350$.

## Subsection 6.6: Advanced Extension: Probabilistic ML with Quantiles and Conformal Calibration

### 1. Claim
Quantile gradient boosting predicts asymmetric prediction bands that adapt to state-dependent volatility, while split conformal calibration adjusts those bands on held-out residuals to guarantee valid finite-sample empirical coverage.

### 2. Plain-Language Definitions
- **Point Forecast vs Prediction Interval:** A point forecast predicts a single central value; a prediction interval provides lower and upper bounds $[\hat{L}, \hat{U}]$ expected to contain the real value with a specified probability (e.g. 80%).
- **Pinball (Quantile) Loss:** An asymmetric loss function (`reg:quantileerror` in XGBoost) that penalizes positive and negative errors with different weights, training the tree to estimate conditional percentiles directly.
- **Split Conformal Calibration:** A distribution-free technique that calculates nonconformity scores (e.g. absolute residuals) on a held-out calibration set to scale interval widths, guaranteeing exact finite-sample empirical coverage without assuming Gaussian errors.
- **Empirical Coverage:** The percentage of actual test observations falling within the prediction band ($N_{inside} / N_{total}$).
- **Interval Sharpness:** The average width of the interval ($\hat{U} - \hat{L}$); smaller width with correct coverage indicates higher precision.

### 3. Dataset & Splits
- **Dataset:** German Daily Electricity Load (`de_electricity_load_daily.csv`).
- **Chronological 3-Way Split:**
  - **Train Set:** `2017-01-01` to `2019-06-30` (910 days) — fits point and quantile XGBoost models.
  - **Calibration Set:** `2019-07-01` to `2019-12-31` (184 days) — held-out fold to calculate calibration nonconformity quantiles.
  - **Test Evaluation Set:** `2020-01-01` to `2020-09-30` (274 days) — evaluates out-of-sample coverage and sharpness across normal and volatile regimes.

### 4. Target, Nominal Levels & Protocol
- **Target:** Daily load $y_t$.
- **Nominal Coverage Levels:** $80\%$ ($\alpha = 0.20$) and $90\%$ ($\alpha = 0.10$).
- **Calibration Protocol (Conformalized Quantile Regression - CQR):**
  - Train quantile models $\hat{q}_{\alpha/2}$ and $\hat{q}_{1-\alpha/2}$ on Train via `xgb.XGBRegressor(objective="reg:quantileerror", quantile_alpha=...)`.
  - On Calibration set, compute nonconformity scores $E_i = \max(\hat{q}_{\alpha/2}(x_i) - y_i, y_i - \hat{q}_{1-\alpha/2}(x_i))$.
  - Find the $1-\alpha$ finite-sample quantile $Q_{1-\alpha}(E, \text{level} = \lceil (n+1)(1-\alpha) \rceil / n)$.
  - Calibrated test interval: $[\hat{q}_{\alpha/2}(x_t) - Q_{1-\alpha}, \hat{q}_{1-\alpha/2}(x_t) + Q_{1-\alpha}]$.

### 5. Methods Compared & Baselines
- **Method 1 (Naive Homoskedastic Gaussian):** Point forecast $\hat{y}_t \pm z_{\alpha/2} \hat{\sigma}_{train}$.
- **Method 2 (Classical Statistical):** ETS / ARIMA parametric prediction interval.
- **Method 3 (Raw Quantile XGBoost):** `xgb.XGBRegressor(objective="reg:quantileerror", quantile_alpha=0.10)` and `quantile_alpha=0.90`.
- **Method 4 (Conformalized Quantile XGBoost):** CQR calibrated on held-out residuals.
- **Metrics:** Empirical Test Coverage (%) vs Nominal ($80.0\%$), Mean Interval Width (MW), and Coverage breakdown by Calm vs Peak Load regime.
- **Default UI State:**
  - Nominal Level: `"80% Confidence"`
  - Active View: `"Interval Bands & Out-of-Bounds Misses"`
  - Method: `"Conformalized Quantile XGBoost vs Naive Gaussian"`

### 6. Expected Observable in Default Chart
- The Naive Gaussian interval has a constant static width, over-covering on quiet weekends but suffering clustered misses during winter cold snaps.
- Raw Quantile XGBoost dynamically adapts to weekend drops and weekday volatility, but distribution shift causes raw test coverage to dip below nominal (e.g. ~74% instead of 80%).
- Conformalized Boosting restores test coverage to the exact target range ($80.0\% \pm 2\%$), visibly bounding test observations while maintaining dynamic, feature-dependent band widths.
- Red "miss" markers clearly identify extreme outliers, demonstrating honest calibration.

### 7. Falsifier & Mitigation
- **Falsifier:** Conformalized boosting achieves less than $75\%$ coverage on the test set for an $80\%$ nominal target, or lower bound exceeds upper bound ($\hat{L} > \hat{U}$).
- **Mitigation:** Enforce monotonic bounds ($\hat{U} = \max(\hat{U}, \hat{L})$). If distribution shift across 2020 violates exchangeability, implement rolling 90-day conformal calibration.
